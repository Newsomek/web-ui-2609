# QA2.1 - Role-Aware Review & Equivalence Governance

Date: 2026-09-03

QA2.1 adds the minimum governance workflow needed before testing persistence and backups.

## Added

- Local prototype personas representing purchasing, management, physician-owner, and non-owner physician roles.
- Permission-based product-equivalence approval rather than owner-only approval.
- Review queue for pending human decisions.
- Escalation/assignment of an equivalence review to an authorized physician reviewer.
- Practice-approved-equivalent state distinct from exact match.
- Rejected-equivalent state that is remembered and no longer re-suggested by analysis.
- Decision attribution: who, role, when, source/basis, and notes.
- Decision history retained when an authorized reviewer changes an approval decision.
- Approved equivalence can affect opportunity totals only after explicit practice approval.
- Review assignments and decisions included in local persistence and JSON backup payloads.

## Important boundary

PracticeSpend records that a practice-authorized reviewer approved two products as equivalent for purchasing analysis. PracticeSpend itself does not make or represent a clinical-equivalence determination.

## QA2.3 - Bulk review, delegation, and physician-owner workflow

QA2.3 addresses the practical concern that a physician owner may want to review some items personally, delegate others to another authorized physician, and avoid processing a large queue one item at a time.

- Review queue filters: All pending, Needs my review, Unassigned, Assigned by me.
- Multi-select review checkboxes plus Select visible / Clear selection.
- Assign selected to me for reviewers already authorized for the selected review types.
- Assign selected to another eligible reviewer for users with review-assignment authority.
- Assignee options are permission-filtered; assignment never grants authority.
- Review selected workflow for sequential review without returning to the queue after each decision.
- Bulk approve / Not equivalent actions for selected product-equivalence reviews when the acting user is authorized for all selected items.
- Shared source/basis and notes fields for deliberate batch decisions.
- Separate assignment/reassignment audit history with who, role, assignee, and timestamp.
- Assignment history is retained in the final decision record after the pending assignment is cleared.

## QA2.4 - completed review lifecycle

Added completed-review management so approvals and rejections are not dead-end records. Authorized users can inspect the full decision history, reopen a completed review into the pending queue, or override the current decision while preserving the superseded outcome. Reopened approved equivalences no longer count as approved opportunities until reviewed again. Override/reopen actions preserve actor, role, timestamp, prior status, source/basis, and notes in the decision history.

## QA2.6 - Review volume, invoice provenance, and readable precision

QA2.6 adds a realistic five-item pending equivalence review workload to the demo. Three demo items are pre-assigned to public physician personas and two remain unassigned so delegation and queue filters can be demonstrated immediately. All review assignments remain fictional demo content.

Normal routing language is now **Assign for review** rather than **Escalate for review**. Escalation is reserved for a future exception/policy workflow.

Every demo invoice now contains ingestion provenance: method, person who added it, timestamp, source file/system, import batch, and source document ID. The Invoices table surfaces the ingestion source, invoice details show an Added to PracticeSpend provenance card, and suspected duplicates show original-versus-duplicate provenance side by side.

CSV/XLSX imports and manual invoice entry now create the same provenance structure so it persists naturally through local storage and JSON backup/export.

Display precision was reduced for readability while retaining full internal numerical precision: normalized unit costs generally display to 3 decimals below $1 and 2 decimals at or above $1. Opportunity calculations state that unrounded underlying values are used instead of exposing long decimal strings.

Automated checks: PASS through QA2.6.
