# PracticeSpend — Roadmap and Commercialization

## Phase 0 — Working Prototype

Cost target: effectively $0 infrastructure.

Capabilities:

- GitHub Pages;
- synthetic demo data;
- CSV/XLSX import;
- manual invoice entry;
- local browser persistence;
- export/reset;
- core deterministic analyses;
- polished five-minute demo.

Decision question:

> Does this solve a real enough problem that James/Heather want to test their own data?

## Phase 1 — Modern Dermatology Pilot

Only if they validate the concept.

- use non-PHI purchasing information;
- normalize real vendor/item history;
- measure actual findings;
- identify missing workflow/features;
- establish baseline versus value found;
- do not overbuild cloud infrastructure yet unless multi-device/shared access is needed.

Decision question:

> Does the product find or prevent enough cost/time leakage to justify paying for it?

## Phase 2 — Commercial MVP

If Modern Dermatology demonstrates meaningful value and other practices validate the pain:

- hosted authentication;
- organization/tenant isolation;
- shared practice access;
- centralized invoice storage;
- robust backups;
- automated invoice ingestion provider;
- scheduled analysis;
- alerts;
- vendor negotiation reports;
- basic billing/subscription.

## Phase 3 — Purchasing Intelligence Platform

Potential additions:

- contract price management;
- rebate/threshold tracking;
- quote comparison;
- pre-purchase order review;
- price alerts;
- vendor scorecards;
- better equivalent-item review;
- accounting/procurement exports/integrations.

## Phase 4 — Practice Economics

Only if customer demand supports expansion:

- inventory economics;
- expiration exposure;
- equipment ROI;
- procedure supply COGS using non-patient aggregate inputs;
- retail product economics;
- capacity and staffing scenarios;
- peer benchmarking.

## Standalone-company hypothesis

If validated, PracticeSpend would likely be better structured as a standalone company rather than a Stratos Engine product or a product owned by a dermatology practice.

Potential founder roles:

- Kelly: product, software, architecture, technical operations, commercialization execution.
- James: dermatologist perspective, practice-owner validation, industry credibility and relationships.
- Heather: practice-owner/operations perspective, product/commercial experience, industry credibility and relationships.

No ownership, funding, or company formation should be assumed before product validation.

## Funding principle

If James/Heather later fund development, distinguish:

- direct product/infrastructure expenses;
- compensation for Kelly's development work;
- ownership/investment terms.

The prototype should exist before that conversation so the funding request is tied to something demonstrable rather than vaporware.
